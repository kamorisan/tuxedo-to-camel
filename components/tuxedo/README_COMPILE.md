# C Implementation Compilation Guide

How to compile the Tuxedo /Q C server without full Tuxedo runtime libraries.

---

## Problem

C implementation requires:
- ✅ Headers: `atmi.h`, `tmqueue.h` (we have these!)
- ❌ Libraries: `libtux.so`, `libbuft.so`, `libfml.so` (not extracted)

The JAR files contain binaries and headers, but **not** the shared libraries.

---

## Solution: Stub Functions

Create stub implementations of Tuxedo API functions for compilation testing.

### Approach 1: Headers-Only Build with Stubs

**Makefile.c-headers-only**:
- Compiles with SDK headers
- Links against stub functions (no libtux.so needed)
- Fallback queue works normally
- Tuxedo /Q calls return TPENOENT (expected without QSPACE)

**Usage**:
```bash
make -f Makefile.c-headers-only
./tuxedo_q_server
```

### Approach 2: Full Runtime (Requires libtux.so)

**Options**:
1. **Extract from runtime image**: 
   ```bash
   podman run --rm oracle/tuxedo:22.1.1.0.0 cat /u01/oracle/tuxHome/tuxedo22.1.1.0.0/lib/libtux.so > sdk/lib/libtux.so
   ```
   
2. **Install full Tuxedo**: Use installer with swap configured

3. **Use prebuilt libraries**: If you have access to a Tuxedo server

---

## Compilation Steps

### Step 1: Build SDK Image (Optional)

```bash
cd components/tuxedo-base-sdk
podman build -f Dockerfile.standalone -t tuxedo-sdk:22.1.1.0.0 .
```

### Step 2: Compile with Stubs

```bash
cd components/tuxedo

# Using Podman
podman run --rm --platform linux/amd64 \
  -v $(pwd):/workspace \
  -v $(pwd)/../tuxedo-base-sdk/sdk:/u01/oracle/tuxHome/tuxedo22.1.1.0.0 \
  -w /workspace \
  oraclelinux:8 \
  bash -c "
    yum -y install gcc make libmicrohttpd-devel && \
    make -f Makefile.c-headers-only
  "
```

### Step 3: Test Binary

```bash
# Run server
podman run --rm -p 8080:8080 \
  -v $(pwd):/workspace \
  -w /workspace \
  oraclelinux:8 \
  ./tuxedo_q_server

# Test endpoints (in another terminal)
curl -X POST http://localhost:8080/enqueue -d "Test message"
curl http://localhost:8080/dequeue
curl http://localhost:8080/health
```

## Stub Functions

**src/tuxedo_stub.c** (auto-generated by Makefile):

```c
int tpinit(TPINIT *tpinfo) {
    fprintf(stderr, "[STUB] tpinit called\n");
    return 0;  // Success
}

int tpenqueue(char *qspace, char *qname, TPQCTL *ctl, 
              char *data, long len, long flags) {
    fprintf(stderr, "[STUB] tpenqueue: qspace=%s, qname=%s\n", 
            qspace, qname);
    tperrno = TPENOENT;  // Queue not found
    return -1;
}

int tpdequeue(char *qspace, char *qname, TPQCTL *ctl, 
              char **data, long *len, long flags) {
    fprintf(stderr, "[STUB] tpdequeue: qspace=%s, qname=%s\n", 
            qspace, qname);
    tperrno = TPENOENT;
    return -1;
}
```

These stubs:
- Allow compilation without libtux.so
- Return expected error codes
- Trigger fallback queue logic
- Enable testing of HTTP/REST layer

## Troubleshooting

### Compilation Error: undefined reference to `tpinit`

**Cause**: Forgot to build stub file

**Solution**:
```bash
make -f Makefile.c-headers-only stub
make -f Makefile.c-headers-only
```

### Runtime Error: libtux.so not found

**Expected** with stub build. Use fallback queue.

**To fix**: Extract/install full Tuxedo runtime libraries.

### QSPACE Error: TPENOENT

**Expected** with stub functions. Fallback queue will activate.
